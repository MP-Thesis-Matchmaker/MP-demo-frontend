# Styles

Global styling for the demo frontend. The structure follows hui-client's
`projects/shared/src/styles`, with one theme instead of one per customer. Colours come from
`docs/branding/themis-banner.png` in backend-core, and every colour works in both light and dark mode.

## Files and load order

`angular.json` → `styles[]` loads these in this order:

| File | What it holds |
|---|---|
| `core/_global-setup.scss` | The Angular Material theme (`mat.theme`), dark-surface overrides, densities, FontAwesome CSS. |
| `core/styles.scss` | Bootstrap 5.3 compiled from source with THEMIS Sass variables, the Bootstrap↔Material token bridge, and app-wide classes (`.info-banner`, `.fading-bottom-ruler`, `.mb-mat`, …). |
| `theme/themis.scss` | Brand fonts (self-hosted via `@fontsource`), `--themis-*` custom properties, and the banner's typographic classes (`.themis-wordmark`, `.themis-eyebrow`, `.tagline`, `.themis-rule-stack`). |
| `html-tags.styles.scss` | Plain `h1`–`h5`, `p`, `a`, `button`, `html`/`body`. |
| `material/customization.styles.scss` | Material component tweaks and modifier classes (`.color-inv`, `.less-rounded`, `.mat-lg-button`, `.secondary-color`, `.size-sm`, `.is-readonly`, …). |
| `helpers.styles.scss` | Small utilities (`.pointer`, `.ellipsis-overflow`, `.text-themis-*`). |

`core/base-colors.scss` and `core/vars.scss` emit no CSS. They hold the palettes, breakpoints and
compile-time helpers that the files above `@use`. `includePaths: ["src/styles"]` lets component
styles write `@use 'core/vars' as vars;` too.

## How light and dark work

Everything runs off one mechanism, the CSS `color-scheme` property:

1. **Material.** `mat.theme()` with `theme-type: color-scheme` emits every `--mat-sys-*` token as
   `light-dark(<light>, <dark>)`. The browser picks the half that matches the element's
   `color-scheme`.
2. **The default.** `html { color-scheme: light dark }` follows the operating system.
3. **The user's choice.** `ThemeService` (`src/app/services/theme.service.ts`) sets
   `color-scheme` on `<html>` to `light` or `dark`, or removes it for "system". It also sets
   `data-bs-theme`, which is how Bootstrap 5.3 switches modes.
4. **Bootstrap.** Its body background, text and border colours are pinned to the Material tokens
   (`styles.scss`), so the two libraries can't disagree.

**The rule: colours that have to follow the mode are tokens, never Sass values.** Write
`var(--mat-sys-on-surface)`, not `vars.neutral(10)`. A Sass colour is fixed when the CSS is
compiled. hui-client is light-only, so its fixed `$hui-*` colours work there; in this app they
would leave black text on a black background. Where a fixed pair is unavoidable (the warning
banner, success text), write both halves explicitly:
`light-dark(#{vars.warning(20)}, #{vars.warning(90)})`.

## Where the palette comes from

`core/base-colors.scss` is generated by
`ng generate @angular/material:theme-color --primary-color='#C0A8F8'`, using the banner's lavender
accent. Primary tone 80 (`#d1bcff`) becomes the dark-mode primary and is close to the banner;
light mode uses tone 40 (`#67529b`). Dark surfaces are pulled from Material's grey `#141317`
toward the banner's black (`$dark-surface` in `vars.scss`).

To change the brand colour, regenerate `base-colors.scss` with a new seed. Don't hand-edit tones.

## Differences from hui-client

- **`mat.theme()` instead of `mat.define-theme()`** with `system-variables-prefix: sys`. hui's
  setup emits `--sys-*` variables while component tokens read `--mat-sys-*` (hui's own README §4).
  Here there is only `--mat-sys-*`.
- **`vars.scss` emits no CSS.** hui's version reprinted its colour classes into every bundle that
  used it.
- **Bootstrap is compiled once.** hui's `customization.styles.scss` compiled it again through an
  unused `@use "../core/styles"`.
- **One brand stylesheet** (`theme/themis.scss`) instead of runtime-swapped per-customer bundles.
- **Font Awesome Free** instead of the vendored Pro sets, so the duotone colour classes are gone.
